# The Last Word War

## Project Strategy v1.0

Author: Victor A. Adeyemi  
Date: 2026-06-17  

## Core Development Principle

Build → Test → Learn → Refine

The project should avoid building features endlessly without testing whether the game is fun, fair, and understandable.

## First Public Playtest Goal

Target: 10 real players

Questions to answer:
- Is the game fun?
- Are the rules intuitive?
- Is the timer useful?
- Do players understand the last-word mechanic?
- Do players want another round?

Success metric:

Players voluntarily ask for another round.

## Public Deployment Strategy

Use Vercel for the first public web demo.

At v0.1.0, avoid:
- User accounts
- Database
- Online multiplayer
- Complex authentication

The first deployed version should simply allow people to open a browser and play locally.

## Educational Direction

Potential modes:
- Physics Mode
- History Mode
- Cryptography Mode
- German Mode
- Literature Mode
- Scientific Communication Mode

Educational validation should test whether the game improves engagement, recall, reasoning, and subject-specific vocabulary.

## Intellectual Property Strategy

Preserve:
- Git commits
- Git tags
- Rulebook
- Game Design Document
- Victory conditions
- Game engine specifications
- Development journal
- Release notes

Avoid publicly exposing internal design documents too early.

Prefer sharing playable demos over sharing the full internal archive.

## Feature Evaluation Rule

Before adding any feature, ask:

1. Does it make the game more fun?
2. Does it make the game more fair?
3. Does it make the game easier to understand?

If the answer is no to all three, do not build it yet.
